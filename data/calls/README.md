# Тестовые звонки

Описание записей — `index.json` (контракт №7). Эталонный транскрипт `NNN.txt`: одна реплика на строку,
`caller: …` (мошенник / звонящий) или `user: …` (мы). Для моно-записей роли в транскрипте всё равно
размечены — по ним считается WER, а `listen()` выдаёт для моно `speaker = unknown`.

| Файлы | Схема | Каналы |
|---|---|---|
| 001–009 | мошенничество (схема в `index.json`) | стерео, кроме 006 и 007 |
| 010–012 | без мошенничества: уведомление банка, курьер, звонок сына | 011 — моно |

## Важно: сейчас это синтез речи, а не постановочные звонки

Все 12 `.wav` собраны скриптом `make_tts_calls.py` из транскриптов голосом macOS `say` (Milena).
Их хватает, чтобы гонять конвейер «звук → реплики → агент → UI», но ТЗ требует живые постановочные
записи (один играет мошенника, другой — жертву), не меньше 5 по сценариям Александра.
Когда запись готова — положите её под тем же именем, поправьте транскрипт под реально сказанное
и обновите строку в `index.json`. Синтетический голос распознаётся заметно лучше живого, поэтому WER
в `audio/asr_report.md` на этих записях — нижняя граница.

Стерео: левый канал — caller, правый — user. Номера вымышленные (+7999000xxxx); у 001–004, 006,
011 и 012 номера совпадают с демо-БД (`python -m storage.seed_demo`), чтобы `lookup_number` показал историю.

Пересобрать синтетические записи (только macOS): `python data/calls/make_tts_calls.py --force`.
