# Реальные разговоры с мошенниками (расшифровки YouTube)

21 видео, где блогеры-пранкеры разговаривают по телефону с мошенниками, 8 ч 13 мин, 4237 исходных реплик.
Исходник — автоматические расшифровки (WhisperX large-v3 + диаризация pyannote): `датасет_реплики.jsonl`,
`датасет_видео.jsonl` и `датасет_расшифровки.md` — это одни и те же данные в трёх видах; сборщик берёт первый.

## Что было не так и что исправлено

- **Метки «Спикер 1/2/…» ничего не говорят о роли** и перепутаны: в 599 из 4237 реплик (14 %) слиты слова и мошенника,
  и жертвы. Даже при лучшем сопоставлении «метка → роль» внутри видео 12 % предложений попали бы не на ту сторону.
- Реплики разрезаны на **предложения** (11 636), и роль определена для каждого по смыслу разговора.
  Разметку сделали 7 субагентов Claude, по 3 видео на каждого; результат выборочно проверен вручную.
  Это **разметка моделью, а не людьми**: ошибки есть, особенно в коротких «Да», «Алло» и в цыганских перепалках в конце видео.
- Каждое видео — **один звонок** со схемой из `data/schemes/` и этапами, привязанными к предложениям.
  Для этого заведены две новые схемы — в базе не было ни одной подходящей:
  - `escort-prepayment` — предоплата за интим-услуги по фейковой анкете (14 звонков);
  - `salon-booking-extortion` — вымогательство за «сорванную бронь» в интим-салоне (7 звонков).
- Длинные последовательности цифр (карты, телефоны) заменены на `[номер]`.

## Файлы

| Файл | В git | Что это |
|---|---|---|
| `build.py` | да | сборка: `python data/calls/real/build.py --src ~/Downloads/датасет_реплики.jsonl` |
| `labels.tsv` | да | роль каждого предложения, `<id>\t<код>`; id = `vNN-tTTT-sS` (видео, реплика, предложение) |
| `episodes.json` | да | звонок в каждом видео: границы, схема, этапы (`first_id` — первое предложение этапа), легенда |

| `calls.jsonl` | нет | по строке на звонок: схема, легенда, персонажи, этапы, `max_stage`, статистика ролей |

Тексты разговоров в git не кладём: ТЗ запрещает класть в репозиторий записи реальных разговоров с мошенниками
(«используем как источник для текста схем»), а здесь ещё и чужой контент с YouTube. Чтобы получить их локально,
положите исходник и запустите `build.py`. Если команда решит, что расшифровки можно хранить, — уберите их
из `data/calls/real/.gitignore`.

## Как этим пользуется агент

- **Классификация** идёт через схемы: `escort-prepayment` и `salon-booking-extortion` индексируются вместе с остальными
  (контракт №1), их `typical_phrases` — реальные фразы мошенников из этих видео (без мата и явных ошибок распознавания).
- **Прогон звонка целиком:** `listen(AudioSource(kind="file", path="data/calls/real/transcripts/real-05.txt"), "real-05")`
  отдаёт реплики транскрипта как Utterance (без распознавания звука). Когда появится `agent.run` (контракт №7),
  тот же путь передаётся в `--source file --path …`.
- **Оценка:** `dialogs.jsonl` даёт правильные `scheme_id` и `stage_n` для каждой фразы мошенника.

### Деление на dev и отложенные видео

`typical_phrases` новых схем взяты **только** из dev-видео. Отложенные видео в схемы не попадали — на них честно проверять
поиск и агента (и собирать из них eval-набор, контракт №6, origin = independent).

| Схема | dev (фразы для схемы) | отложены |
|---|---|---|
| escort-prepayment | 01, 04, 06, 07, 08, 10, 11, 12 | 09, 13, 14, 15, 18, 19 |
| salon-booking-extortion | 02, 03, 05, 16 | 17, 20, 21 |

Быстрая проверка без LLM: BM25 с лемматизацией pymorphy3 по всем 32 схемам, окно из 8 последних фраз мошенника,
отложенные видео (212 окон): схема top-1 — 53 %, hit@3 — 84 %; этап при верной схеме — точно 42 %, ±1 — 62 %.
Почти все ошибки — путаница двух новых схем между собой (обе про интим-салон, «кассы», залоги и угрозы);
«одна из двух салонных схем» — 92 %. Подгонять схемы под отложенные видео нельзя — это утечка теста.

### Этапы

Номер этапа в звонке может идти назад: мошенники ходят по кругу «деньги не дошли → залог → снова не дошли».
Этап назначается по позиции в разговоре (последний начавшийся), а не по максимуму. `max_stage` в `calls.jsonl` — максимум.
