# Приложение для iPhone: архитектура

Приложение — тонкий клиент. Телефон слушает разговор микрофоном и шлёт звук на сервер,
сервер (на время тестов — этот компьютер) делает всё остальное: распознаёт речь, ищет схему,
пишет подсказки, сохраняет кейс. На телефоне нет ни моделей, ни логики агента.
По возможностям приложение повторяет веб-интерфейс (`ui/web`).

```
iPhone                                             Компьютер (ui.server, --host 0.0.0.0)
┌────────────────────────────┐                     ┌──────────────────────────────────────┐
│ MicCapture (AVAudioEngine) │                     │ POST /api/calls {source:"remote"}    │
│   → 16 кГц моно PCM16      │  POST …/audio?seq=N │   → agent.run --source remote        │
│   → куски по 250 мс        │ ───────────────────▶│      stdin ← PCM                     │
│ AudioUploader (очередь)    │                     │      VAD → Whisper → агент           │
│                            │   SSE …/events      │      → data/runs/<call_id>.jsonl     │
│ EventStream → CallState    │ ◀───────────────────│ GET /api/calls/<id>/events           │
│   → SwiftUI                │                     │                                      │
└────────────────────────────┘                     └──────────────────────────────────────┘
```

## Ограничение iOS, из которого всё следует

iOS не даёт сторонним приложениям ни звук сотового звонка, ни микрофон во время него:
как только начинается звонок, запись в приложении прерывается (`AVAudioSession` interruption).
Обойти это нельзя, публичного API нет. Поэтому режим работы один:

- **Телефон как второе устройство.** Звонок идёт на другом телефоне по громкой связи,
  iPhone с приложением лежит рядом и слушает микрофоном. Так же сейчас работает режим «Микрофон»
  в веб-версии. Реплики приходят без ролей (`speaker = unknown`).

Кроме того, приложение запускает на сервере тестовые звонки и записи — как веб-версия.

## Что меняется на сервере

1. Новый источник звука `remote`: `AudioSource.kind = "remote"`, агент читает из stdin
   сырой PCM (16 кГц, моно, s16le). Конец stdin — конец звонка.
2. `ui.server` принимает звук от телефона и пишет его в stdin процесса агента.
3. `ui.server --host 0.0.0.0` — слушать локальную сеть. Запросы не с этого компьютера
   проходят только с кодом доступа.
4. Сервер объявляет себя в сети через Bonjour (`_antifraud._tcp`), чтобы адрес не вводить руками.

## API для телефона

Все прежние адреса `ui/server.py` остаются без изменений. Добавляется:

| Запрос | Что делает |
|---|---|
| `GET /api/info` | Без кода доступа. `{"app": "antifraud", "api": 1, "auth": true}` — проверка, что это наш сервер. |
| `POST /api/calls` с `{"source": "remote", "phone": "+7…"?}` | Запускает звонок со звуком от телефона. Ответ 201 — как у остальных источников. |
| `POST /api/calls/<id>/audio?seq=N` | Тело — `application/octet-stream`, PCM s16le 16 кГц моно, до 1 МБ. Ответ 204. |
| `POST /api/calls/<id>/stop` | Как раньше. Для `remote` сначала закрывает stdin агента: он дораспознаёт остаток и штатно заканчивает звонок. |

Правила для `/audio`:

- `seq` начинается с 0 и растёт на 1. Кусок с `seq` не больше уже принятого — повтор после
  обрыва сети: ответ 204, звук второй раз не пишется. Пропуск номеров допустим (кусок потерян).
- 404 — звонка нет; 409 — звонок не `remote` или уже закончился; 400 — нет `seq`, пустое тело
  или нечётное число байт; 413 — больше 1 МБ.
- Если звука нет 90 секунд (телефон пропал; порог больше очереди телефона в 60 секунд), сервер заканчивает звонок сам, как по «Стоп».

Код доступа:

- Нужен, только если запрос пришёл не с `127.0.0.1` / `::1`. Веб-интерфейс на самом компьютере
  работает как раньше.
- Заголовок `Authorization: Bearer <код>`. Нет или неверный — 401 `{"error": "…"}`.
- Код — 6 цифр. Берётся из `ANTIFRAUD_TOKEN`, иначе создаётся при запуске и печатается в консоль
  вместе с адресом в локальной сети.

## Устройство приложения

Папка `ios/`. Почти весь код — в локальном Swift-пакете, чтобы его можно было собрать и
протестировать командой `swift build` / `swift test` на macOS без Xcode. Xcode нужен только
чтобы запустить приложение в симуляторе или на телефоне.

```
ios/
├── project.yml                  # XcodeGen → Antifraud.xcodeproj (сам проект не коммитим)
├── App/                         # тонкая оболочка: @main, Info.plist, иконка
└── AntifraudKit/                # Swift-пакет, iOS 17+ и macOS 14+
    ├── Sources/AntifraudCore/   # только Foundation: модели, сеть, состояние звонка
    ├── Sources/AntifraudAudio/  # микрофон → PCM16 16 кГц
    ├── Sources/AntifraudUI/     # SwiftUI: экраны и их модели
    └── Tests/AntifraudCoreTests/
```

| Модуль | Что внутри |
|---|---|
| `AntifraudCore` | Модели контрактов (`AgentEvent` с типизированным payload, `Scheme`, `CallCase`, `NumberInfo`, ответы моста). `APIClient` — все запросы моста. `EventStream` — SSE с продолжением по `Last-Event-ID`. `CallState` — состояние экрана из событий, перенос `ui/web/src/callView.js`. `AudioUploader` — очередь кусков звука с `seq` и повторами. `ServerStore` — адрес и код доступа. |
| `AntifraudAudio` | `MicCapture`: `AVAudioEngine` → конвертация в 16 кГц моно Int16 → `AsyncStream<Data>` кусками по 250 мс. Настройка `AVAudioSession` и прерывания — под `#if os(iOS)`. |
| `AntifraudUI` | Экраны и `@Observable`-модели. `CallSession` связывает микрофон, отправку и поток событий. |

Экраны (то же, что в вебе):

| Вкладка | Экран | Аналог в вебе |
|---|---|---|
| Звонок | Новый звонок: «Слушать микрофоном», тестовые звонки, записи, номер звонящего | `NewCall.jsx` |
| | Идущий звонок: вердикт, «положите трубку», подсказка, плашки, этапы схемы, расшифровка | `CallPage.jsx` |
| | Отчёт после звонка | `Report.jsx` |
| История | Кейсы и звонки, поиск по номеру, отчёт по нажатию | `History.jsx` |
| Схемы | Каталог и карточка схемы с этапами | `Schemes.jsx` |
| Сервер | Адрес (найденные через Bonjour или вручную), код доступа, готовность сервера (`/api/health`) | боковая панель |

Жизненный цикл живого звонка:

```
idle → starting (POST /api/calls) → live (микрофон + отправка + SSE)
     → stopping (POST …/stop, микрофон выключен, SSE дочитывается до call_ended)
     → finished (отчёт)
```

- Экран заблокирован или приложение свёрнуто — запись продолжается (`UIBackgroundModes: audio`).
- Прерывание записи системой (входящий звонок на этот же iPhone) — показываем причину,
  после окончания прерывания запись возобновляется сама.
- Сеть пропала — куски копятся в очереди (до 60 секунд звука, дальше старые выбрасываются)
  и досылаются по порядку; поток событий переподключается с `Last-Event-ID`.

## Порядок работ

1. Сервер: источник `remote`, приём звука, доступ из сети — `docs/ios/tz-server.md`.
2. Приложение — `docs/ios/tz-app.md`. Пишется параллельно с сервером: стык — таблица API выше.
3. Проверка без Xcode: `pytest`, `swift build`, `swift test`, сквозной прогон «файл → /audio → события» скриптом.
4. Проверка с Xcode (ставит владелец компьютера): симулятор (микрофон Mac), затем iPhone.
