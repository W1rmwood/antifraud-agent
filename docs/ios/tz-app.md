# ТЗ: приложение «Антимошенник» для iPhone

Сначала прочитай `docs/ios/architecture.md`: там схема, API сервера, состав модулей и экранов.
Это ТЗ уточняет, что именно написать. Серверную часть (`remote`, `/audio`, код доступа)
параллельно делает другой исполнитель — пиши строго под таблицу API из архитектуры.

## Условия, в которых ты работаешь

- **Xcode на этой машине нет**, есть только Command Line Tools (Swift 6.3, macOS SDK).
  Собрать приложение под iOS нельзя. Поэтому весь код, кроме оболочки, лежит в Swift-пакете
  `ios/AntifraudKit` с платформами iOS 17 и macOS 14 и **обязан собираться `swift build` на macOS**.
  Всё, чего нет на macOS (`AVAudioSession`, `UIKit`), — под `#if os(iOS)` / `#if canImport(UIKit)`;
  такой код компилятор здесь не проверит, поэтому держи его маленьким и простым.
- Тесты — `swift test` (Swift Testing, `import Testing`; XCTest в Command Line Tools нет).
- Сторонних зависимостей нет: только системные фреймворки.
- Xcode-проект описывается `ios/project.yml` (XcodeGen). `xcodegen` не установлен и ставить его
  не надо — пользователь поставит сам; сам `.xcodeproj` в репозиторий не кладём (`ios/.gitignore`).

## Модули

### AntifraudCore (только Foundation)

- **Модели** — `Codable`, `Sendable`. `AgentEvent`: `call_id`, `seq`, `ts`, `type`, payload —
  enum с вариантом на каждый тип события и вариантом `unknown` для типов, которых приложение
  не знает (новое событие на сервере не должно ронять разбор). Даты — ISO 8601 с долями секунды
  и без. Ответы моста: `Sources`, `CallStatus`, `Run`, `Health`, `SchemeBrief`, `Scheme`,
  `CallCase`, `NumberInfo`, `ServerInfo`.
- **`APIClient`** — `actor` или `Sendable`-структура поверх `URLSession`: все адреса моста, включая
  `info`, `startCall`, `sendAudio(callID:seq:data:)`, `stop`, `upload`. Заголовок
  `Authorization: Bearer`. Ошибки — один тип `APIError` с текстом из `{"error": …}` сервера;
  401 — отдельный случай (экран просит код).
- **`SSEParser`** — чистый разбор строк SSE (`id`, `event`, `data`, комментарии, пустая строка).
  **`EventStream`** — `AsyncThrowingStream` событий `agent` / `process` / `end` через
  `URLSession.bytes(for:)`; при обрыве переподключается с `Last-Event-ID`, пауза растёт до 5 с;
  после `end` заканчивается; 404 — ошибка «лога звонка нет», без повторов.
- **`CallState`** — значение, `mutating func apply(_ event: AgentEvent)`. Результат обязан
  совпадать с `callView.js`: строки расшифровки, схема и её этапы, текущий этап, плашки,
  последняя подсказка модели и последний «положите трубку», вердикт (`scheme` / `warning` /
  `none`), номер и сведения о нём, отчёт, признак конца звонка.
- **`AudioUploader`** — `actor`. Принимает куски PCM, шлёт строго по порядку с растущим `seq`,
  по одному запросу за раз. Ошибка сети — повтор того же `seq` с паузой. В очереди не больше
  60 секунд звука: при переполнении выбрасываются самые старые куски (их `seq` пропускается).
  Ответы 404 и 409 — звонок закончился, отправка прекращается. Наружу — состояние
  (`sending`, `retrying`, `stopped`) и счётчик потерянных секунд.
- **`ServerStore`** — адрес и код доступа в `UserDefaults` (ключи доступа тут не секрет уровня
  Keychain: это шестизначный код тестового сервера в локальной сети).
- Утилиты: нормализация и показ номера (+7 и 10 цифр), слияние истории как `mergeHistory`,
  форматирование времени и длительности.

### AntifraudAudio

- **`MicCapture`**: `AVAudioEngine`, tap на `inputNode`, `AVAudioConverter` → 16 000 Гц, моно,
  Int16 little-endian; наружу `AsyncStream<Data>` кусками ровно по 250 мс (8000 байт), последний
  кусок при остановке — какой получился. Чистая часть (накопление и нарезка байт на куски) —
  отдельным типом без AVFoundation, чтобы покрыть тестами.
- Под `#if os(iOS)`: `AVAudioSession` — категория `.record` (режим `.measurement`), запрос
  разрешения на микрофон, обработка `interruptionNotification` (пауза → возобновление) и
  `routeChangeNotification`. Наружу — состояния `running`, `interrupted`, `denied`, `failed(text)`.

### AntifraudUI

- `@Observable`-модели на `@MainActor`, SwiftUI, `NavigationStack`, `TabView` из четырёх вкладок
  (см. таблицу экранов в архитектуре). Тёмная и светлая темы, Dynamic Type, VoiceOver-подписи
  у кнопок без текста.
- **`CallSession`** — один на идущий звонок, ведёт цикл `idle → starting → live → stopping →
  finished` из архитектуры: запускает звонок на сервере, для `remote` включает `MicCapture` и
  `AudioUploader`, читает `EventStream`, складывает события в `CallState`. Для остальных
  источников (`file`, `replay`) — только поток событий.
- **Новый звонок.** Главная кнопка «Слушать микрофоном» и короткое пояснение: положите телефон
  рядом с тем, на котором идёт разговор по громкой связи. Поле номера звонящего (необязательное).
  Ниже — тестовые звонки и записи с сервера (`/api/sources`), загрузка своей записи через
  `fileImporter` (`/api/upload`). Если сервер занят звонком (`busy`) — предложить открыть его.
  Источников `mic` и `loopback` сервера в приложении нет.
- **Идущий звонок.** Сверху вниз: вердикт крупно (нет признаков / есть признаки / схема и
  уверенность) → «Положите трубку…» → подсказка модели → плашки-предупреждения → этапы схемы с
  отметкой текущего → расшифровка (новые реплики снизу, автопрокрутка, если пользователь не
  отлистал вверх). Индикатор записи и состояния отправки, кнопка «Стоп». На новую плашку и на
  объявление схемы — вибрация (`UINotificationFeedbackGenerator`, под `canImport(UIKit)`).
  Пока идёт живой звонок, экран не гаснет (`isIdleTimerDisabled`).
- **Отчёт**, **История** (кейсы + звонки, поиск по номеру через `/api/numbers/<phone>`),
  **Схемы** (список и карточка) — содержимое как в вебе.
- **Сервер.** Найденные в сети серверы (`NWBrowser`, `_antifraud._tcp`) и ручной ввод адреса;
  поле кода; проверка `/api/info` и `/api/health` с понятными причинами: сервер не найден, не наш
  сервер, неверный код, что не готово для звонка (список проверок с командами починки).
  Первый запуск без сохранённого сервера открывает этот экран.

### Оболочка `ios/App` и `project.yml`

- `AntifraudApp.swift` — `@main`, показывает корневой экран из `AntifraudUI`.
- `Info.plist`: `NSMicrophoneUsageDescription`, `NSLocalNetworkUsageDescription`,
  `NSBonjourServices` (`_antifraud._tcp`), `UIBackgroundModes` → `audio`,
  `NSAppTransportSecurity` → `NSAllowsLocalNetworking` (сервер в локальной сети отдаёт http).
- `project.yml`: приложение iOS 17+, bundle id `ru.antifraud.app`, зависимость от локального
  пакета, автоматическая подпись (команда задаётся пользователем в Xcode).
- `ios/README.md`: как собрать и запустить — установить Xcode, `brew install xcodegen`,
  `xcodegen` в `ios/`, открыть проект, выбрать команду подписи; как запустить сервер для
  телефона; что проверить в симуляторе и на телефоне; ограничение iOS про сотовые звонки.

## Тесты (`swift test`)

- Разбор каждого файла `data/mock_events/*.jsonl` целиком без ошибок (файлы читаются по пути от
  корня репозитория через `#filePath`, копировать их в пакет не нужно).
- `CallState` на этих файлах: схема, этап, число плашек, вердикт, отчёт — ожидания выпиши,
  посмотрев в сами файлы; неизвестный тип события не ломает разбор.
- `SSEParser`: многострочный `data`, комментарии-heartbeat, `id`, обрыв посреди события.
- `AudioUploader` на подменённом транспорте (протокол, не настоящая сеть): порядок `seq`,
  повтор после ошибки, переполнение очереди, остановка на 409.
- Нарезка PCM на куски, нормализация номера, слияние истории.

## Правила

- Работаешь только в `ios/`. Остальной репозиторий — читать можно, менять нельзя.
- Не коммить, не переключай ветки, не пушь. Ничего не устанавливай (ни Xcode, ни brew-пакеты).
- Не запускай и не останавливай Ollama и `ui.server`.
- Комментарии в коде — по-русски, короткие, только там, где неочевидно «почему».
- Swift 6: начни в режиме Swift 6 со строгой проверкой конкурентности; если упрёшься в неё
  надолго в UI-модуле — переведи этот модуль на `.swiftLanguageMode(.v5)` и напиши об этом.
