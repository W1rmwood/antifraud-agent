# ТЗ: сервер принимает звук от телефона

Сначала прочитай `docs/ios/architecture.md` — раздел «API для телефона» и есть контракт,
менять его нельзя: под него параллельно пишется приложение. Нашёл в нём ошибку — не правь
молча, опиши в отчёте.

## Что должно получиться

Телефон в той же сети запускает звонок, шлёт куски PCM, получает события агента — и всё это
через `ui/server.py`. Веб-интерфейс на самом компьютере работает как раньше, без кода доступа.

## Работы

### 1. Источник `remote` в агенте

- `contracts/models.py`: `AudioSource.kind` — добавить `"remote"`. Проверь все места, где
  перечислены виды источника (payload `call_started`, `CallRequest`, тесты контрактов,
  `ui/web` — веб должен нормально показать звонок с таким источником).
- `audio/capture.py`: `open_remote(source, stream=None)` — асинхронный генератор блоков float32
  16 кГц из потока байт PCM s16le (по умолчанию `sys.stdin.buffer`). Чтение блокирующее — в
  отдельном потоке, event loop не блокировать. Блоки по ~30 мс, как у микрофона. Конец потока —
  конец генератора. Нечётный хвост байт склеивается со следующим чтением.
- `audio/stream.py`: `listen` для `kind="remote"` идёт через `_listen_live` с `open_remote`.
  После конца потока недосказанная фраза дораспознаётся (это уже делает `segmenter.flush()`).
- `agent/run.py`: `--source remote`. Конец stdin заканчивает звонок штатно: отчёт, `save_case`,
  `call_ended`, код возврата 0. SIGTERM работает как раньше.

### 2. Запуск и подача звука — `agent/ui_api.py`

- `start_call(source="remote")` запускает процесс с `stdin=PIPE`. Остальным источникам stdin
  не нужен — оставь `DEVNULL`.
- `CallProcess`: `feed(data: bytes)` — записать звук в stdin (потокобезопасно; процесс уже
  умер — исключение, которое мост превратит в 409), `close_audio()` — закрыть stdin.
- `stop()` для `remote`: сначала `close_audio()`, дальше прежняя логика — ждём штатного конца,
  не дождались за `STOP_TIMEOUT_S` — `terminate`, потом `kill`.

### 3. Мост — `ui/server.py`

- `GET /api/info`, `POST /api/calls` с `source: "remote"`, `POST /api/calls/<id>/audio?seq=N` —
  точно по таблице и правилам из архитектуры (коды ответов, повтор `seq`, лимит 1 МБ).
- Сторож тишины: 90 секунд без звука по `remote`-звонку — закончить его как по «Стоп».
  Порог — константа, в тестах подменяется.
- `--host` (по умолчанию `127.0.0.1`). Код доступа — по разделу «Код доступа»: запросы с
  loopback проходят без него, остальным на `/api/*` (кроме `/api/info`) нужен
  `Authorization: Bearer`. Сравнение — `hmac.compare_digest`. Статика фронта для внешних адресов
  тоже закрыта: без кода — 401.
- При запуске с внешним адресом печатать адрес в локальной сети и код:
  `Телефон: http://192.168.1.5:8642, код 123456`.
- Bonjour: при внешнем адресе на macOS запускать `dns-sd -R "Антимошенник" _antifraud._tcp local <порт>`
  дочерним процессом и гасить его при выходе. Нет `dns-sd` (Linux, Windows) — молча пропустить.
- Только стандартная библиотека, новых зависимостей нет.

### 4. Проверочный клиент — `scripts/` не трогаем

`audio/send_remote.py`: `python -m audio.send_remote data/calls/001.wav --server http://127.0.0.1:8642 [--token …] [--phone …]` —
ведёт себя как телефон: запускает `remote`-звонок, шлёт файл кусками по 250 мс в реальном темпе,
печатает события из SSE, в конце жмёт «Стоп». Им проверяется вся цепочка без iPhone.

### 5. Тесты и документация

- `tests/`: `open_remote` (нарезка блоков, нечётный хвост, конец потока); `listen` с
  `kind="remote"` на подменённом распознавании; мост — `/api/info`, запуск `remote`, приём звука,
  повтор `seq`, 400/404/409/413, код доступа (loopback без кода, внешний адрес с кодом и без),
  сторож тишины; CLI `--source remote`. Сеть и модели в тестах не нужны — смотри, как устроены
  `tests/test_ui_server.py`, `tests/test_audio_live.py`, `tests/fakes/`.
- `docs/frontend.md`: новые адреса. `README.md`: короткий раздел «Телефон как микрофон» —
  как запустить сервер для телефона.

## Правила

- Работаешь в текущей папке и текущей ветке. Не коммить, не переключай ветки, не пушь.
- Не трогай `ios/` и `docs/ios/architecture.md` — там работает другой исполнитель.
- Комментарии и докстринги — по-русски, в стиле соседнего кода. Строки до 120 символов.
- Python — `.venv/bin/python` (3.12). Ничего не устанавливай.
- Ollama и `ui.server` на порту 8642 не запускай и не останавливай — ими может пользоваться
  владелец компьютера. Для ручной проверки бери другой порт и `.txt`-транскрипты или фейки.
